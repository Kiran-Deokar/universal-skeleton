Vue 3 & Nuxt

A template ref plus the onMounted / onBeforeUnmount pair is all the wiring Vue needs. Works the same in <script setup>, Options API and Nuxt 3.

Install

npm install universal-skeleton

TypeScript types are included; no extra packages.

<script setup> — scan on mount, destroy on unmount

<script setup lang="ts">
import { ref, onMounted, onBeforeUnmount } from 'vue';
import { SkeletonLoader } from 'universal-skeleton';

const card = ref<HTMLElement | null>(null);
let handle: ReturnType<typeof SkeletonLoader.scan> | null = null;

onMounted(() => {
  if (!card.value) return;
  handle = SkeletonLoader.scan(card.value, { effect: 'fade', theme: 'auto' });
  loadUser();
});

onBeforeUnmount(() => {
  handle?.destroy();
  handle = null;
});

async function loadUser() {
  const user = await SkeletonLoader.while(
    fetch(`/api/users/${id}`).then(r => r.json()),
    card.value!,                       // while() re-scans; the old overlay is replaced
    { minDuration: 500, effect: 'fade' },
  );
  // skeleton already removed — assign data
}
</script>

<template>
  <section ref="card">
    <!-- your real markup; render your empty/loading state here -->
    <h2>Loading…</h2>
  </section>
</template>
You do not need both patterns at once. Prefer one: either scan() + explicit destroy, or while() around the promise. If you use while(), drop the manual handle bookkeeping and keep only onBeforeUnmount cleanup via SkeletonLoader.restore(card.value).

Options API

export default {
  mounted() {
    this.handle = SkeletonLoader.scan(this.$refs.card, { effect: 'shimmer' });
  },
  beforeUnmount() {
    this.handle?.destroy();
  },
};

The <skeleton-screen> element

Vue 3 handles custom elements natively. Configure the compiler once (vue-loader / Vite plugin) so unknown tags skip attribute casting:

// vite.config.ts
export default defineConfig({
  plugins: [vue()],
  compilerOptions: {
    isCustomElement: (tag) => tag === 'skeleton-screen',
  },
});
<skeleton-screen :loading="loading ? '' : null" effect="pulse">
  <article class="product">…</article>
</skeleton-screen>

With isCustomElement configured you can also pass booleans directly: :loading="loading" works because Vue sets the attribute for custom elements.

Nuxt 3

  • SSR: importing the package on the server is safe — it is guarded. Scanning needs the DOM, so it belongs in lifecycle hooks which only run client-side.
  • For components you want excluded from SSR entirely, wrap in <ClientOnly>; the onMounted pattern above works either way.
  • Auto-imports: put the import in the component (or re-export from a composable) — universal-skeleton is not auto-imported by default.

Gotchas

  • Template refs need the DOM. Scan in onMounted, never at setup top-level — the element does not exist yet during SSR or hydration.
  • v-if swaps destroy the node. If the scanned element is removed by v-if, the overlay goes with it — Vue's cleanup handles the handle; scanning a stable wrapper element avoids churn.
  • Reactive lists. When rows render after the scan (async list), call handle.update() in a watch on the list length, or scan again.
  • Keepalive. With <KeepAlive>, re-scan in onActivated if the cached component should re-show a skeleton.
