Angular

Angular gives you two clean hooks: ngAfterViewInit to scan (the view exists and has real geometry) and DestroyRef to clean up. No zone or renderer tricks required.

Install

npm install universal-skeleton

Works with standalone components, NgModules, Angular 14+ and the latest majors. TypeScript types included.

Scan in AfterViewInit, clean up with DestroyRef

import { Component, ElementRef, ViewChild, AfterViewInit, OnDestroy, inject } from '@angular/core';
import { SkeletonLoader } from 'universal-skeleton';

type SkeletonHandle = ReturnType<typeof SkeletonLoader.scan>;

@Component({
  selector: 'app-profile',
  standalone: true,
  template: `
    <section #card>
      <!-- your real markup; render the empty/loading state here -->
      <h2>Loading profile…</h2>
    </section>
  `,
})
export class ProfileComponent implements AfterViewInit, OnDestroy {
  @ViewChild('card') card!: ElementRef<HTMLElement>;
  private handle: SkeletonHandle | null = null;
  private destroyRef = inject(DestroyRef);

  ngAfterViewInit() {
    this.handle = SkeletonLoader.scan(this.card.nativeElement, {
      effect: 'shimmer',
      theme: 'auto',
    });
    this.load();

    this.destroyRef.onDestroy(() => this.handle?.destroy());
  }

  private load() {
    this.api.getProfile().subscribe({
      next: (profile) => { this.profile = profile; },
      complete: () => { this.handle?.destroy(); this.handle = null; },
    });
  }

  ngOnDestroy() { this.handle?.destroy(); }
}

Prefer DestroyRef (or ngOnDestroy) — the overlay must not outlive the view.

while() with HttpClient

Turn the observable into a promise and let the library manage the skeleton:

import { firstValueFrom } from 'rxjs';

async load() {
  const profile = await SkeletonLoader.while(
    firstValueFrom(this.api.getProfile()),
    this.card.nativeElement,
    { effect: 'pulse', minDuration: 400 },
  );
  this.profile = profile;   // skeleton already removed
}

Signals / zoneless notes

  • scan() is plain DOM work — it runs fine outside Angular change detection and does not need runOutsideAngular.
  • In zoneless apps (experimental provideZonelessChangeDetection()), nothing changes: scan in ngAfterViewInit, destroy when data arrives.
  • For signal-based re-scans, wrap handle.update() in afterRenderEffect or call it when your list length signal changes.

The <skeleton-screen> element

Add CUSTOM_ELEMENTS_SCHEMA once per component (or globally), then use the element in templates:

import { CUSTOM_ELEMENTS_SCHEMA } from '@angular/core';

@Component({
  selector: 'app-product',
  standalone: true,
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  template: `
    <skeleton-screen [attr.loading]="loading ? '' : null" effect="wave">
      <article class="product">…</article>
    </skeleton-screen>
  `,
})
Angular binds custom-element attributes as strings. [attr.loading]="loading ? '' : null" adds the attribute while loading and removes it after — the component re-syncs on every change.

Angular Universal / SSR

  • Importing the package on the server is safe — style injection and element registration are guarded when HTMLElement is missing.
  • ngAfterViewInit and ngOnDestroy run in the browser for client-hydrated views, so the pattern above is SSR-safe without platform checks.
  • If a component is rendered server-side only (API transfers state), you never scan it — perfect: the skeleton only appears during real client loading.

Gotchas

  • Scan in AfterViewInit, not ngOnInit. At init the view is not rendered; geometry would be zero.
  • *ngIf swaps. If *ngIf removes the scanned node, the overlay disappears with it — destroy the handle to stay consistent, or scan a wrapper that always stays.
  • Dynamic lists. Rows added after the scan need handle.update() — call it in ngAfterViewChecked guarded by a length check, or on the data event.
  • Route changes. Destroy on component teardown (shown above) — handles are per-element and never global.
