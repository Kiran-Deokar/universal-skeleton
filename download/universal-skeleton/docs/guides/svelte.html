Svelte & SvelteKit

bind:this gives you the raw element; onMount (or the runes $effect) gives you the timing. Svelte's minimalism matches the library's — two lines of wiring.

Install

npm install universal-skeleton

TypeScript types included. Works with Svelte 3, 4 and 5 (runes or not).

Svelte 5 — $effect + bind:this

<script lang="ts">
  import { SkeletonLoader } from 'universal-skeleton';

  let card: HTMLElement;
  let user: User | null = $state(null);

  $effect(() => {
    if (!card) return;
    const handle = SkeletonLoader.scan(card, { effect: 'sheen', theme: 'auto' });
    return () => handle.destroy();     // cleanup on re-run / unmount
  });

  async function load() {
    user = await SkeletonLoader.while(
      fetch(`/api/users/${id}`).then(r => r.json()),
      card,
      { minDuration: 500 },
    );
  }
</script>

<section bind:this={card}>
  <!-- real markup; render your empty/loading state here -->
  <h2>Loading…</h2>
</section>

Svelte 3 / 4 — onMount + onDestroy

<script>
  import { onMount, onDestroy } from 'svelte';
  import { SkeletonLoader } from 'universal-skeleton';

  let card;
  let handle;

  onMount(() => {
    handle = SkeletonLoader.scan(card, { effect: 'fade' });
    load();
  });

  onDestroy(() => handle?.destroy());

  async function load() {
    const user = await SkeletonLoader.while(fetchUser(), card);
    user = user;
  }
</script>

<section bind:this={card}>…</section>
In Svelte, top-level let assignments reactively update only when using $state (Svelte 5) or the user = user invalidation trick (classic). The skeleton itself does not care — it works on the DOM directly.

The <skeleton-screen> element

<skeleton-screen loading={loading ? '' : undefined} effect="blink">
  <article class="order">…</article>
</skeleton-screen>

Svelte compiles unknown tags to customElements calls automatically. Pass the boolean attribute as an empty string (or undefined to remove it) to be safe across compilers.

SvelteKit

  • SSR: importing the package in +page.svelte is safe — the module is guarded when document is missing.
  • Timing: onMount / $effect never run on the server, so scans are browser-only by construction.
  • Load functions: you may not need a skeleton at all if data resolves in +page.ts before render — skeletons shine for client-side re-fetches, invalidate() reloads and streamed data.
  • Streaming: with streamed promises (+page.server.ts returning pending promises), scan the section in onMount and destroy when the stream resolves.

Gotchas

  • bind:this timing. The bound variable is set before onMount runs — that is the right moment to scan. At module top-level it is still undefined.
  • {#if} blocks. If an {#if} removes the scanned node, the overlay goes too; destroy the handle in the same branch transition, or scan a wrapper that always exists.
  • Transitions. Elements mid-transition: have changing geometry — call handle.update() after the transition ends (or scan the container, not the animating child).
  • each lists. Rows added after scanning need handle.update(); a reactive statement on the array length is a clean place for it.
