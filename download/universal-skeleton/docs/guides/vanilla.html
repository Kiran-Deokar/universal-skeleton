Vanilla JS & CDN

No framework, no build step — one script tag and one function call. This is the quickest way to see the library working, and every other guide builds on the same three ideas.

Install

Option A — CDN script tag (zero setup)

<script src="https://unpkg.com/universal-skeleton/dist/index.iife.min.js"></script>
<!-- or jsDelivr: https://cdn.jsdelivr.net/npm/universal-skeleton/dist/index.iife.min.js -->

This registers the global UniversalSkeleton and injects the stylesheet automatically. Nothing runs until you call it.

Option B — npm with a bundler

npm install universal-skeleton
import { SkeletonLoader } from 'universal-skeleton';
// CommonJS works too: const { SkeletonLoader } = require('universal-skeleton');

Your first skeleton

Take any real markup — this page never needs placeholder HTML. Then scan it:

<div id="card">
  <h2>Ada Lovelace</h2>
  <p>First programmer in history.</p>
  <button>Follow</button>
</div>

<script>
  const handle = UniversalSkeleton.SkeletonLoader.scan('#card');
  // …data arrives / view is ready:
  // handle.destroy();
</script>

The scan measures the heading, paragraph and button, then paints matching grey blocks on top: per-line pill bars for text, a rounded rect for the button. The real content stays in the DOM underneath — it is only hidden by CSS while the skeleton shows.

Loading data with while()

The most common loop — skeleton while fetching, restore automatically, even on error:

const { SkeletonLoader } = UniversalSkeleton;

const posts = await SkeletonLoader.while(
  fetch('/api/posts').then(r => r.json()),
  '#post-list',
  { effect: 'fade', minDuration: 600 }
);
renderPosts(posts);   // skeleton already removed at this point
  • minDuration keeps the skeleton on screen at least that long so fast responses do not flash.
  • If the promise rejects, the skeleton is still removed and the error propagates normally.

Fine-tune with data attributes

Add attributes directly in your HTML where the automatic guess needs help:

<img src="me.jpg" class="avatar" data-skeleton="circle">
<!-- ↑ a round image becomes a circle block -->

<div class="chart" data-skeleton="rect" data-skeleton-radius="12">
  <!-- whole chart becomes ONE rounded block, children skipped -->
</div>

<span class="live-badge" data-skeleton-ignore>LIVE</span>
<!-- ↑ stays fully visible while everything around it skeletons -->

<div data-skeleton-color="#c7d2fe">…</div>

See the API reference for the full list: circle, rect, text, none, ignore plus -radius, -color, -highlight.

Pick an effect & theme

SkeletonLoader.scan('#card', {
  effect: 'wave',    // shimmer | wave | pulse | fade | blink | sheen | bounce | none
  theme: 'auto',     // light | dark | auto — auto follows the OS
  duration: 1200,    // ms per cycle
});

// switch at runtime, no rebuild:
handle.setEffect('pulse');
handle.setTheme('dark');

Global theming is pure CSS — set the variables once and every skeleton follows:

:root {
  --usk-color: #e5e7eb;
  --usk-highlight: #f3f4f6;
  --usk-radius: 8px;
  --usk-duration: 1.4s;
}

The Web Component alternative

When you already know a region will load late, declare it instead of scanning:

<skeleton-screen loading effect="shimmer">
  <!-- your real markup lives here, untouched -->
  <h2>Order #1042</h2>
  <p>Ships tomorrow</p>
</skeleton-screen>

<script>
  // toggle with one attribute — no JS needed:
  //   skeletonScreenEl.removeAttribute('loading')
</script>

Gotchas worth knowing

  • Scan after layout. Elements need real dimensions. Call scan() after the DOM is parsed and visible — e.g. on DOMContentLoaded or right before an Ajax call.
  • Hidden elements are skipped. Anything display:none at scan time produces no blocks; call handle.update() after you show it.
  • Resizes are handled. With the default responsive: true, a ResizeObserver rebuilds blocks when the card changes size.
  • Reduced motion. Every effect is disabled under prefers-reduced-motion: reduce — nothing to configure.
  • Multiple scans are safe. Scanning the same target twice replaces the previous skeleton.
