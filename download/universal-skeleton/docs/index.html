Why universal-skeleton

Most skeleton libraries ask you to re-declare your UI twice: once for real, once as grey blocks. This one refuses.

⚙

Auto-scan, never hand-draw

SkeletonLoader.scan(el) walks the DOM, measures every visible leaf and paints blocks at the exact coordinates — text becomes per-line pills, round avatars become circles, buttons become rounded rects.

✨

Eight effects, switchable live

shimmer · wave · pulse · fade · blink · sheen · bounce · none. Switch at runtime with handle.setEffect() — no rebuild. prefers-reduced-motion is honored automatically.

🌙

Light, dark and auto themes

One theme option picks the palette. auto follows the OS color scheme with zero JavaScript. Fine-tune everything with the --usk-* CSS variables.

🧪

One Web Component for every framework

<skeleton-screen loading> wraps your real markup and toggles the skeleton via a single attribute — the same element works in React, Vue, Angular, Svelte and plain HTML.

📈

Stays correct while things move

A built-in ResizeObserver rebuilds blocks when the layout changes; handle.update() re-measures after your data mutates the DOM. Blocks never go stale.

💾

Zero deps, tiny, typed

No runtime dependencies, ~4 KB gzipped, ships ESM + CJS + CDN bundle. TypeScript declarations are included — there is no @types package to install.

How it works — three lines total

  1. Load the library. Via npm, or one <script> tag from the CDN. Styles are injected automatically.
  2. Scan. SkeletonLoader.scan('#card') covers your element with a skeleton that mirrors its real geometry. Everything underneath stays intact and untouched.
  3. Restore. handle.destroy() — or SkeletonLoader.restore('#card') — removes every trace. Or wrap a promise with SkeletonLoader.while() and let it restore itself, even on failure.
// your real markup — no placeholder components, no duplicated layout
const handle = SkeletonLoader.scan('#feed', { effect: 'shimmer' });

const posts = await SkeletonLoader.while(fetch('/api/feed').then(r => r.json()), '#feed', {
  minDuration: 600,        // keep the skeleton on screen at least this long
  effect: 'fade',          // any of the 8 effects
  theme: 'auto',           // light | dark | auto (follows the OS)
});

renderFeed(posts);          // skeleton is already gone — the real UI shows through
The scan never mutates your content: the real UI stays in the DOM underneath the overlay, hidden by CSS while the skeleton shows. Destroying the handle restores everything exactly as it was.

The whole API at a glance

CallWhat it does
SkeletonLoader.scan(target, options?)Auto-mirrors target as a skeleton. Returns a handle: update(), setEffect(), setTheme(), destroy().
SkeletonLoader.while(source, target, options?)Shows the skeleton while a promise (or function) runs, restores automatically — even when it rejects. Passes the result through.
SkeletonLoader.restore(target)Removes an active skeleton. Safe no-op if none.
SkeletonLoader.isActive(target)true while a skeleton is showing.
<skeleton-screen loading>Drop-in Web Component: toggles via the loading attribute; effect, theme, color, highlight-color, duration, radius attributes.
